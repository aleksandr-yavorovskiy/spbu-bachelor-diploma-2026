\section{Описание решения}
\subsection{Требования к продукту}
    \label{subsec:task1}

    При исследовании проблематики предметной области был собран и проработан ряд требований, представленный ниже.

    \vspace{1em}

    \textbf{Бизнес-требования:}
    \begin{enumerate}
        \item Обеспечение возможности ручного набора и редактирования кириллических текстов.
    \end{enumerate}

    \vspace{1em}

    \textbf{Функциональные требования:}
    \begin{enumerate}
        \item Импорт и экспорт файлов в форматах \pdf{}, DOCX, TXT;
        \item Генерация \pdf{} с использованием \TeX{};
        \item Конвертация текста между шрифтами;
        \item Встроенная клавиатура для ввода спецсимволов.
    \end{enumerate}

    \vspace{1em}

    \textbf{Нефункциональные требования:}
    \begin{enumerate}
        \item Кроссплатформенность;
        \item Интуитивно понятный интерфейс.
    \end{enumerate}


\subsection{Архитектура решения}
    \label{subsec:task2}

    Чтобы удовлетворить требованиям кроссплатформенности и простоты интерфейса, было принято решение реализовать инструмент в виде одностраничного веб-приложения (Single-Page App) \cite{jadhav2015single}.

    Frontend приложения разработан с помощью \vuejs{}, в то время как внутренняя логика (backend) написана на \python{} веб-фреймворке \fastapi{}. Для реализации импорта и экспорта файлов использовались \python{}-библиотеки \docx{} и \pypdf{}.

    API бэкэнда представляет из себя следующий набор обработчиков:
    \begin{itemize}
        \item auth:
        \begin{itemize}
            \item POST \textbf{/api/auth/register/}~--- регистрация нового пользователя.
            \item POST \textbf{/api/auth/token/}~--- вход пользователя, получение токена.
            \item GET \textbf{/api/auth/verify/}~--- проверка валидности токена.
        \end{itemize}

        \item fonts:
        \begin{itemize}
            \item GET \textbf{/api/fonts/}~--- получение списка доступных шрифтов.
            \item POST \textbf{/api/fonts/}~--- загрузка нового шрифта (требуется аутентификация).
            \item GET \textbf{/api/fonts/\{font\_name\}/}~--- скачивание файла шрифта по имени.
            \item DELETE \textbf{/api/fonts/\{font\_name\}/}~--- удаление шрифта (требуется аутентификация).
        \end{itemize}

        \item import:
        \begin{itemize}
            \item POST \textbf{/api/import/}~--- импорт текста из файла (TXT, PDF, DOCX).
        \end{itemize}

        \item export:
        \begin{itemize}
            \item POST \textbf{/api/export/pdf/}~--- экспорт текста в PDF.
        \item POST \textbf{/api/export/docx/}~--- экспорт текста в DOCX.
        \end{itemize}

        \item compile:
        \begin{itemize}
            \item POST \textbf{/api/compile/}~--- компиляция текста в PDF (предпросмотр).
        \end{itemize}

        \item ping:
        \begin{itemize}
            \item GET \textbf{/api/ping/}~--- проверка работоспособности сервера.
        \end{itemize}
    \end{itemize}

    Компиляция \pdf{} файла с текстом, набранным пользователем, происходит по следующему сценарию:
    \begin{enumerate}
        \item пользователь набирает текст в поле редактора и настраивает параметры отображения (шрифт, размер, отступы) с помощью верхнего меню при необходимости;
        \item пользователь нажимает кнопку \enquote{Предпросмотр PDF} или комбинацию клавиш Ctrl+S;
        \item frontend получает содержимое поля редактора и параметры отображения текста, отправляет их на backend с помощью HTTP POST запроса на адрес \textbf{/api/compile/};
        \item backend принимает информацию, вставляет ее в шаблон структуры \TeX{} файла, предварительно обработав текст во избежание ошибок компиляции и отображения, и компилирует \pdf{} с помощью \xelatex{};
        \item при успешной компиляции итоговый \pdf{} отправляется на frontend и показывается пользователю в правой части рабочего пространства; при возникновении ошибки сообщение также направляется от backend-части на frontend и показывается пользователю.
    \end{enumerate}

    Остальные сценарии взаимодействия с текстовыми файлами (импорт, экспорт) происходят по такому же принципу.

    Диаграмму классов бэкэнд-части приложения можно видеть на Рис.~\ref{fig:classdiagram}. Сервисный слой представляет из себя три класса (\textbf{ImportService}, \textbf{ExportService}, \textbf{CompilationService}), которые наследуюься от абстрактного \textbf{BaseService} и содержат в себе бизнес-логику приложения. Логика импорта/экспорта реализована в классах, наследующихся от \textbf{BaseImporter} и \textbf{BaseExporter}. Компиляция \pdf{} происходит с помощью конвейера \textbf{ProcessingPipeline} (включающего в себя \textbf{LatexEscaper} и \textbf{SoftBreaksProcessor}), \textbf{LatexBuilder} (отвечающего за создание \TeX{} файла) и \textbf{LatexCompiler} (отвечающего за взаимодействие с \xelatex{} и получение итогового \pdf{}).

\subsection{Особенности реализации}
    \label{subsec:task3}

    Приложение контейнеризировано с помощью \docker{}, а также создан \makefile{} с целями (targets), необходимыми для разработки, тестирования и развертывания. Для запуска инструмента на целевом сервере достаточно установить значение переменной \textbf{EXPERT\_PASSWORD} (необходимо для возможности добавления шрифтов в редактор) в файле \textbf{./backend/.env} и вызвать команду \textbf{make deploy}.

    В приложении существуют конвертации двух видов:
    \begin{enumerate}
        \item конвертация текста из кириллицы в глаголицу и обратно.
        \item конвертация текста между шрифтами;
    \end{enumerate}
    Оба вида реализованы с помощью одного механизма, основанного на словарях и работающего во frontend-части приложения. В случае конвертации между кириллицей и глаголицей каждый символ текста заменяется на соответствующий ему символ, определенный в JSON-словаре. В случае конвертации между шрифтами этот механизм происходит два раза: сначала текст, набранный шрифтом, переводится аналогичным образом в \unicode{}, а затем из \unicode{} в символы, соответсвующие новому шрифту.

    Проблема отображения длинных слов (в древних кириллических рукописях текст писался без пробелов) была решена следующим образом: в случае, если длина слова превышает максимально допустимое значение, определенное в конфигурации приложения, само слово оборачивается в специальную \TeX{}-команду \textbf{\texttt{\textbackslash{}seqsplit\{\}}} из одноименного пакета, позволяющую автоматически разбивать набор символов на строки. Также было добавлено экранирование символов, специфичных для \TeX{}, во избежание ошибок компиляции (например, символ \texttt{\&} заменяется на \texttt{\textbackslash\&}).
